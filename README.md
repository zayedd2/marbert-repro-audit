# Revisiting MARBERT for Arabic Sentiment: Reproducibility and Controlled Evaluation Audit

Code, configs, seeds, package versions, saved predictions and scripts for AI504 Assignment 2 (Introduction to Computational Linguistics, The British University in Dubai). The project re-runs the MARBERT vs AraBERT sentiment comparison of

> [1] M. Abdul-Mageed, A. Elmadany and E. M. B. Nagoudi. *ARBERT & MARBERT: Deep Bidirectional Transformers for Arabic.* ACL-IJCNLP 2021, pp. 7088–7105. <https://aclanthology.org/2021.acl-long.551>

and asks one question: **does MARBERT's advantage over AraBERT stay stable when checkpoint selection, training randomness and the sentiment metric are controlled?**

[![tests](https://github.com/zayedd2/marbert-repro-audit/actions/workflows/tests.yml/badge.svg)](https://github.com/zayedd2/marbert-repro-audit/actions/workflows/tests.yml)

**All 36 runs are complete.** Their per-epoch predictions are in `results/runs/`, and every table, figure and report number is rebuilt from them with one command, without a GPU. The regenerated numbers match the team's own result files exactly (`results/tables/crosscheck_vs_team.csv`).

## Experimental design

| | |
|---|---|
| **Models** | `UBC-NLP/MARBERT` @ `88e1fa19` (original, not v2); `aubmindlab/bert-base-arabertv01` @ `01f6b7d2` ([1] does not name its AraBERT release) |
| **Datasets** | ArSarcasm-Sent (official split, 8,437 / 2,110); ASTD (trained on CAMelSent rebuilt from four sources, 27,394 tweets; official ASTD test, 661); AJGT (our stratified 80/20 split, 1,440 / 360), plus 6 check runs on the authors' AJGT split |
| **Fine-tuning ([1])** | Adam (no weight decay), LR 2e-6 constant, batch 32, max length 256, 25 epochs; fp16; dev and test scored after every epoch |
| **Seeds** | 42, 43, 44 for every configuration; MARBERT and AraBERT share code, data, seeds and GPU (NVIDIA L4) |
| **Historical protocol** (audit item 1, Member 2) | Full training set; best epoch **on test** by the published metric, as [1] did |
| **Independent protocol** (items 2–5, Member 3; main result) | Grouped stratified 10% dev set held out (Member 1); epoch chosen on **dev** with the published metric; test reported at that epoch |
| **Checkpoint diagnostic** (item 3) | In each independent run: best test score over all epochs minus the test score of the dev-selected epoch |
| **Reliability** (item 4) | Per-seed paired MARBERT − AraBERT differences (mean ± SD), and a 95% paired bootstrap over test tweets (B = 1,000), reported separately |
| **Metric choice** (item 5) | Rankings and leads under F1-PN, macro-F1 and accuracy |
| **Reproduced if** | (\|gap\| ≤ 2 points **or** published score inside our seed range) **and** MARBERT > AraBERT on that dataset (fixed in the proposal) |

Every difference from [1] and from the proposal is listed in [`docs/DEPARTURES.md`](docs/DEPARTURES.md) (26 entries).

## Reproducibility measures

* **Pinned models and packages**: Hugging Face revisions in `configs/models.yaml` and `env/model_revisions.json`; package versions in `env/env_lock.json` and every run's `env.json`.
* **Fixed seeds and splits**: seeds 42–44 control head initialisation, dropout and batch order; split membership is committed as ID lists in `data/splits/`, with MD5 checksums of every split file in `data/MANIFEST.json`.
* **Saved predictions**: test (and dev) predictions with class probabilities for all 25 epochs of every run, so any selection rule, metric or statistic can be recomputed without retraining.
* **Verified import**: `import_team_runs.py` re-scores all 1,650 saved prediction sets and stops if any logged score disagrees; `verify_results.py` repeats the check and writes `results/MANIFEST.sha256`.
* **Same statistics as the team**: the paired bootstrap uses the team's procedure and generator (B = 1,000, seed 12345; subgroups B = 2,000, seed 2026), so every interval regenerates exactly.
* **Synthetic runs stay separate**: the smoke test writes only to `results_synthetic/`, watermarks its outputs and is refused inside `results/`.
